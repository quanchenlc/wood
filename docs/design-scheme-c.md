## 1. 术语表

| 术语 | 英文/Key | 定义 |
|------|----------|------|
| 树根 | `root` / `piece` | 计量单位。一棵待伐对象倒地并成功入垛计 **1 树根**。 |
| 刀 | `hit` / `chop` | 一次有效劈砍输入。**物理刀数恢复原版几何切割**（薄到不可劈 / 无可劈块才入垛）；方案 C 曾写的「3 刀/根」已废弃，仅作历史说明。 |
| 主动劈 | `active_chop` | 玩家在线触屏/点击完成的劈砍，消耗日额度。 |
| 离线产出 | `offline_yield` | 离开游戏后按递进计时积攒的待领树根。 |
| 待领 | `pending_claim` | 已产出但尚未领取的树根池，有上限。 |
| 领取 | `claim` | 将待领转入玩家库存（累计量），计入日额度。 |
| 日额度 | `daily_quota` | 当日「主动入垛 + 离线领取」共享上限，默认 **300**。 |
| 可持续砍伐量 | `sustainable_quota` | 叙事层对日额度的称呼；达上限后进入「蓄养」。 |
| 疏伐 | — | 额度未满时的主动/离线产出叙事阶段。 |
| 蓄养 | — | 日额度耗尽后的休息叙事；可看广告临时加额度。 |
| 加速 | `speed_up` | 激励视频效果：缩短离线计时或跳过一段待产时间，**不锁死领取**。 |
| 入垛 | `stacked` | 树根按几何规则劈完并进入柴堆，计入累计砍柴与好友榜（不要求固定刀数）。 |
| 累计砍柴 | `total_pieces` | 历史入垛总数，好友榜主字段。 |

## 2. 核心玩法对接（与现有劈砍）

现有页面/小游戏核心循环：点砍 → 树倒 → 柴入垛。方案 C 在其上叠加「额度 + 离线 + 广告加速 + 好友榜」，不改劈砍手感。

### 2.1 单根流程

1. 生成/展示一棵待伐树根。  
2. 玩家按原版几何规则继续劈砍（`isTooThinToSplit` / 无可劈块），全部处理完 → 入垛。**不**再使用「满 3 刀强制伐倒」。  
3. 入垛成功时 `today_pieces += 1`，`total_pieces += 1`，扣减日额度剩余 1。  
4. 若日额度剩余为 0 → 进入蓄养态（见 §4），不可再主动入垛，除非广告加额度。

> **废弃说明（0.3.0→hotfix）：** 方案 C 初稿曾写「每树根 3 刀」并在 `GameController` 里 `forceFell`。老板否决该手感改动；物理刀数已恢复 pre-0.3.0 几何切割。`hitsPerRoot` 配置已删除。

### 2.2 与离线的关系

- 离线产出的是「已计时完成的待领树根」，领取时 **同样消耗日额度**，并增加 `total_pieces` / `today_pieces`。  
- 领取不要求再砍固定刀数（视为疏伐队已完成物理劳动）；UI 可用「一键领取」+ 短反馈。  
- 主动劈与离线领 **共享** `daily_quota = 300`。

### 2.3 不改动项

- 3D 场景、触屏劈砍手感（原版几何切割）、音效解压向体验维持现状。  
- 一期不做 Soft 著 / 版号相关内容。  
- 广告 **只** 做加速与加额度，**禁止** 用广告墙锁死「领取」按钮。

## 3. 离线递进产出

### 3.1 规则（定稿）

- 计时单位：分钟；产出单位：树根。  
- **前 180 根**：每根耗时 **1 分钟**。  
- **其后**：每满 **20 根** 为一档，该档内每根耗时相对上一档 **×2**。  
- 公式（`n` 为从 1 起的「本周期离线序号」，领取后可从本地进度续算，见 §4）：

```
若 n ≤ 180:
  T(n) = 1 分钟
否则:
  stage = ceil((n - 180) / 20)   // 181–200 → 1, 201–220 → 2, …
  T(n) = 2^stage 分钟
```

### 3.2 递进表示例

| 序号区间 n | 档位 stage | 单根耗时 T | 该档合计时长 | 该档根数 |
|------------|------------|------------|--------------|----------|
| 1 – 180 | 0 | 1 分钟 | 180 分钟（3h） | 180 |
| 181 – 200 | 1 | 2 分钟 | 40 分钟 | 20 |
| 201 – 220 | 2 | 4 分钟 | 80 分钟 | 20 |
| 221 – 240 | 3 | 8 分钟 | 160 分钟 | 20 |
| 241 – 260 | 4 | 16 分钟 | 320 分钟 | 20 |
| 261 – 280 | 5 | 32 分钟 | 640 分钟 | 20 |
| … | … | ×2 | … | 20 |

> 实现提示：不必预生成无穷表；按 `n` 实时算 `T(n)`，用「上次离线结算时间戳 + 累计已产出序号」推进即可。

### 3.3 待领上限

- `pending_claim` 上限 = **200**。  
- 达上限后离线计时暂停（或继续走时间但不增加待领），回线提示「柴棚已满，先领取再继续疏伐」。  
- 广告加速 **不能** 突破待领上限；加速只消耗「未来待产时间」，结果仍受 200 封顶。

### 3.4 目标日玩时长对齐（设计意图）

- 主动劈：按原版几何切割刀数（不固定 3 刀），日常主动约占用 10–20 分钟体感。  
- 离线：挂机攒待领，回线一键领，补足「有收获感」但不强制肝。  
- 合计目标日接触 **15–25 分钟**；超额靠广告加额度自愿延长，非硬门槛。

## 4. 领取与日切

### 4.1 日额度

| 项 | 值 | 说明 |
|----|-----|------|
| `daily_quota` 基础 | **300** | 主动入垛 + 离线领取共享 |
| 日切 | 本地 `Asia/Shanghai` 自然日 00:00 | 与微信开放数据域日字段对齐时用同一时区 |
| 日切重置 | `today_pieces = 0`；日额度恢复为 300 + 当日未过期的广告加额 | 见广告表「加额度」有效期 |
| 累计 | `total_pieces` **不** 日切 | 好友榜主字段 |

### 4.2 领取流程

1. 回线结算：按离开时长与递进表，将可产出根数写入 `pending_claim`（≤200）。  
2. 玩家点「领取」：  
   - `claim = min(pending_claim, daily_remaining)`  
   - `pending_claim -= claim`  
   - `today_pieces += claim`，`total_pieces += claim`  
   - `daily_remaining -= claim`  
3. 若 `daily_remaining == 0` 且仍有 pending：按钮文案改为蓄养态提示，**仍展示待领数字**；可通过广告加额度后再领（不锁死入口）。  
4. **禁止**：必须看广告才能点亮领取。

### 4.3 本地进度字段（一期建议）

| Key | 类型 | 说明 |
|-----|------|------|
| `total_pieces` | number | 累计入垛 |
| `today_pieces` | number | 当日入垛（主动+领取） |
| `today_date` | string `YYYY-MM-DD` | 日切锚点（上海时区） |
| `daily_remaining` | number | 当日剩余额度 |
| `daily_bonus` | number | 当日广告加额尚未消耗部分 |
| `pending_claim` | number | 待领 |
| `offline_index` | number | 下一根离线序号 n（用于 T(n)） |
| `last_offline_ts` | number | 上次离线结算 Unix ms |
| `ad_daily_*` | number | 各广告位当日次数（见 §5） |

存储：一期 **微信用户本地存储**（`wx.setStorage`）+ 开放数据域 KV 同步榜字段；云开发二期再做权威存档。

## 5. 激励视频广告规则

原则：**只加速 / 加额度，不锁领取。** 无插屏。纯 IAA。

### 5.1 广告位表

| 广告位 ID | 触发场景 | 效果 | 日上限（建议） | 备注 |
|-----------|----------|------|----------------|------|
| `AD_OFFLINE_SKIP` | 离线面板 / 待产中 | 跳过 **30 分钟** 等价离线时间（按递进表结算进 pending，仍受待领 200 与日额度约束） | 8 | 加速主位 |
| `AD_QUOTA_PLUS` | 蓄养态 / 额度将尽 | 当日 `daily_quota` **+20**（写入 `daily_bonus`） | 5 | 加额主位 |
| `AD_ACTIVE_BURST` | 主动劈间歇（可选） | 一期可选，默认关闭 | 3 | 档期紧可砍 |
| `AD_CLAIM_DOUBLE` | 领取成功后 | 默认不上，避免与「不锁领取」冲突感 | 3 | enabled: false |

**一期必做**：`AD_OFFLINE_SKIP`、`AD_QUOTA_PLUS`。  
**一期默认不做**：领取强锁、插屏、被动弹广告。

### 5.2 加速结算伪代码

```
function applyOfflineSkip(minutes = 30):
  remain_ms = minutes * 60 * 1000
  while remain_ms > 0 and pending_claim < 200:
    t = T(offline_index) * 60 * 1000
    if remain_ms >= t:
      pending_claim += 1
      offline_index += 1
      remain_ms -= t
    else:
      // 不足一整根：保留碎片进度
      break
```

### 5.3 填充与失败

- 广告拉取失败：提示「疏伐队暂时联系不上，稍后再试」（画布内，不用系统 Toast），不惩罚、不扣次数。  
- 中途关闭未看完：无奖励；以激励回调 `isEnded` 为准。

## 6. 文案与叙事（疏伐 → 蓄养）

### 6.1 世界观一句话

这片林子要靠 **可持续疏伐** 养起来：每天有固定的 **可持续砍伐量**；砍够了就让林地 **蓄养**，明天再来。

### 6.2 状态文案

| 状态 | 标题/短句 | 说明文案示例 |
|------|-----------|--------------|
| 疏伐中 | 今日还可疏伐 N 根 | 适量砍伐，林子才长得更好。 |
| 待领 | 柴棚待取：M 根 | 疏伐队已备好，回来领取即可。 |
| 柴棚满 | 柴棚已满（200） | 先领取再继续疏伐。 |
| 蓄养 | 今日蓄养中 | 已达可持续砍伐量。看一支短片可临时增加疏伐额度。 |
| 加速 | 疏伐加速 | 短片结束后，为你推进一段疏伐进度。 |
| 加额度 | 临时许可 +20 | 护林员特批，今日可持续砍伐量 +20。 |

### 6.3 好友榜相关文案

- 榜标题：`好友砍柴榜`  
- 分数释义：`累计疏伐（入垛）`  
- 空榜：`喊上好友一起来疏伐吧`  

### 6.4 禁用表述

避免：无限砍、光头山、破坏环境、强迫看广告才能领柴。  
统一用：疏伐、蓄养、可持续砍伐量、柴棚。

## 8. 数值验收标准（QA / 策划）

### 8.1 离线递进

- [ ] `n=1…180`：相邻两根间隔均为 1 分钟（允许 ±1s）。  
- [ ] `n=181` 起 2 分钟；`n=201` 起 4 分钟；之后每 20 根翻倍。  
- [ ] `pending_claim` 达 200 后不再增加。  
- [ ] 广告跳过 30 分钟后 pending 与递进表一致，且 ≤200。

### 8.2 日额度与领取

- [ ] 主动入垛 + 领取 ≤ `300 + 当日有效加额`。  
- [ ] 日切（上海 00:00）后 `today_pieces` 归零，基础额度恢复 300。  
- [ ] `total_pieces` 跨日不重置。  
- [ ] 额度耗尽时领取入口仍可见；加额后能领。

### 8.3 劈砍对接

- [ ] 入垛仅在无可劈块时触发（几何规则）；无 forceFell / 固定 3 刀。  
- [ ] 入垛成功才 +1 今日/累计。

### 8.4 广告

- [ ] 未看完无奖励。  
- [ ] 无「必须看广告才能领取」。  
- [ ] 日上限生效。

### 8.5 好友榜

- [ ] 开放数据域可读好友 `total_pieces` 并排序。  
- [ ] 入垛/领取后分数更新。

### 8.6 体验锚点

- [ ] 首日不看广告也能在 15–25 分钟内感到柴堆成长。  
- [ ] 长离线受待领 200 与递进变慢约束。
